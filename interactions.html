Interactions

This page documents only the Discord interactions that exist in Uranium’s current bot code: slash commands, buttons, select menus, modals and autocomplete — and it says so where a type is not implemented.

Last updated: 5 November 2026

Slash commands

Uranium registers 11 top-level slash commands, one per category, with subcommands underneath — 242 subcommands in total in the current code. Slash commands work inside a server only, not in direct messages.

Options can be users, roles, channels, whole numbers, true/false values or text. Some text options have fixed choices, and the AutoMod “rule” option uses autocomplete (see below). Required options must be filled before Discord will send the command.

Prefix and mention commands also exist. The default text prefix is ! (a server can change it), short forms are documented in the in-bot help — for example !help, !b @user spam (ban) and !p 50 (purge) — and mentioning the bot can invoke commands or, where the message does not match a command, the AI. Approved “no-prefix” users and the bot owner have additional modes described in the in-bot help.

Buttons

Buttons are handled either by the message that created them (a collector, usually limited to the person who ran the command) or by the bot’s shared button handler. Current buttons include:

  • Confirm / Cancel — dangerous commands ask for confirmation and expire after 30 seconds; choosing Cancel, or letting it time out, changes nothing.
  • Undo — shown under results that support it; only the moderator who ran the command can use it, and it lasts 10 minutes.
  • Case #… — shows the saved moderation case; Dismiss removes the buttons from a result and only works for the moderator who ran it.
  • Help navigation — Home, Prev, Next, Search and Close in /info help; only the person who opened help can use them.
  • Polls and giveaways — vote buttons (only the poll creator can end a poll) and a giveaway Enter button that toggles your entry.
  • Role panels and tickets — a role button toggles that role on you; a ticket button opens a private ticket channel, and Close inside a ticket works for the ticket owner or a moderator with Manage Channels.
  • Music panel — pause/resume, stop, volume and 24/7 controls; most controls require you to be in the bot’s voice channel, and 24/7 requires Manage Server.
  • AI “Forget this chat” — clears the in-memory AI conversation for you in that channel.
  • Link buttons — some results and member notifications include ordinary URL buttons, for example an appeal link a server has configured.

Select menus

  • Help category menu — in /info help, choose Home, a command category or the short-form guide.
  • Music station menu — in the music panel, choose one of the listed radio stations (SomaFM and Radio Paradise streams in the code).

No other select menus are implemented in the current code.

Modals (pop-up forms)

  • Search commands — the Search button in help opens a one-field form (2–30 characters) and shows matching commands.
  • Edit embed — the owner-only embed builder opens a form with title, description, colour, image URL and footer fields, then previews the embed before sending.

Modals are opened from those buttons and are collected by the same message; Uranium does not register standalone modal-only commands. No modal asks for a password, token or personal document.

Context-menu commands

None are implemented. Uranium registers no right-click (context-menu) commands on users or messages in the current code. The interaction handler routes only autocomplete, slash (chat-input) commands, buttons and string select menus.

Autocomplete

The AutoMod rule option offers matching AutoMod rule names as you type, showing whether each rule is enabled. If nothing matches, no suggestions are shown.

Interaction and bot permissions

  • Many commands define a required Discord permission. Uranium checks your permission and the bot’s permission before running them, and refuses with an explanation if either is missing. Examples: member moderation uses permissions such as Kick Members, Ban Members, Moderate Members and Manage Nicknames; channel tools use Manage Channels; role tools use Manage Roles; server and AutoMod settings use Manage Server; message tools use Manage Messages; voice tools use Mute/Deafen/Move Members.
  • Role position also matters: you generally cannot moderate a member whose highest role is at or above yours, and Uranium cannot manage a member or role at or above its own highest role. Move the Uranium role higher if a role action is refused for that reason.
  • Owner-only (“Premium”) commands are refused for everyone except the bot operator, and a server-wide blacklist can block a user from using the bot at all.
  • The dashboard invite link in the code requests the bot and applications.commands scopes. Server administrators should still review the permissions Discord shows before adding any bot, and give only what their server needs.
  • Run /info setup-check and /info bot-permissions in your server to see what Uranium can and cannot do there.

Error handling and good usage

  • Expected problems are shown as an error embed with a “How to fix” hint — for example missing permissions, a member or role not being found, an invalid ID (IDs are 17–20 digit numbers), an invalid duration such as 10m or 1h30m, or messages too old for Discord bulk deletion.
  • Dangerous actions show the Confirm/Cancel buttons described above. Cancelled or timed-out confirmations make no change.
  • Some interactions are personal: help, music and panel controls check that you are the right user or in the right voice channel, and replies that only you should see are sent as ephemeral (only-visible-to-you) messages.
  • If a button has expired — for example an Undo button after 10 minutes or a poll after a bot restart — run the command again instead of retrying the old message.
  • Usage tips: start with /info help, prefer slash commands so Discord shows you each option, write clear moderation reasons (they are saved in the case record), and test new AutoMod or lockdown settings in a quiet channel first.

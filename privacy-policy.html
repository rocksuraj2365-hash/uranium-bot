Privacy Policy

This policy describes the data practices that are confirmed by Uranium’s current source code. If a practice is not in the code, it is not claimed here.

Last updated: 5 November 2026

Scope and limits: This page was written from the bot, dashboard and storage code in the Uranium repository. A live deployment could run different code or settings, and the operator of that deployment is responsible for keeping this policy accurate. Items marked “needs owner confirmation” are not decided in the code and are listed again in the pull request for this page.

1. Discord IDs and basic information

Uranium works with Discord identifiers because Discord bots cannot function without them. Depending on the feature used, the code processes:

  • Discord user IDs, server (guild) IDs, channel IDs, role IDs and message IDs.
  • Usernames where a feature displays or sends them — for example the signed-in dashboard user, a giveaway host name saved with a giveaway, the author name kept briefly with a deleted message for the “snipe” feature, and usernames included in an AI request context (see section 5).
  • Server names, channel names, icons and avatars returned by Discord, where a command or the dashboard displays them.

2. Moderation cases, warnings, notes and configuration

Uranium’s storage library saves a JSON data file (see section 6). For each Discord server it can store:

Moderation reasons and note text are written by moderators. Do not put sensitive personal information in reasons or notes.

3. Message content

  • Uranium receives message content to run prefix and mention commands, and — in a channel an administrator has set as the AI chat channel — to answer messages with AI.
  • If a message is deleted, the bot keeps the last deleted message for that channel in memory only (its text, author username and ID, and the time) so the owner-only snipe command can show it. This is held in a running-process map, not written to the data file.
  • Poll votes are also held in memory only (which option each user ID chose). Giveaway entrants, by contrast, are saved in the data file as described above.
  • Message content is not written to the moderation data file merely because a message was sent. It can be saved if a moderator puts it in a reason or note, or if it becomes part of another record described here.

4. Discord OAuth and dashboard sessions

  • The dashboard login uses Discord OAuth with the identify and guilds scopes. Uranium exchanges the login code with Discord, then requests your Discord profile and server list from Discord’s API.
  • The dashboard session stores your Discord user ID, display username and avatar, and for each server its ID, name, icon and whether you can manage it (owner, or having the relevant Discord permissions). The OAuth access token itself is used for those requests and is not stored in the session object in the code.
  • The session cookie is set as HTTP-only, with SameSite=Lax, is marked Secure when the site is served over HTTPS, and has a maximum age of seven days in the code. Sessions use the in-memory session store in the current code; the project README describes this as a starter setup.
  • The dashboard API endpoints for your profile and server list reject requests that are not logged in. Logging out destroys the session.
  • Uranium never asks for, and you must never give it, your Discord password or a Discord token.

5. AI requests and Anthropic

  • AI features are optional. They do nothing unless the bot operator has set an Anthropic API key, and a server administrator can turn AI off for that server.
  • When AI is used, Uranium sends a request to Anthropic’s API (api.anthropic.com). The request contains the text you asked (the code truncates a request to 1,500 characters), a short context line containing the server name, channel name, your username and user ID, your relevant Discord permission names and the server prefix, and — if you replied to a message — that message’s author username and text, marked as untrusted and truncated.
  • Uranium also sends Anthropic a list of available Uranium commands so the AI can choose one. If it runs a command for you, that command runs with your own Discord permissions and can create the normal records for that command (for example a moderation case).
  • Recent AI conversation turns are kept in a running-process memory map, keyed by channel and user, holding up to the last ten messages. You can clear them with the AI reset command or the “Forget this chat” button. The code does not write AI chat history to the data file.
  • This policy does not describe Anthropic’s own handling of API requests. Anthropic is a separate provider with its own policies — its retention and training terms for this deployment need owner confirmation.

6. Storage, retention and deletion

  • Bot records are stored in a JSON file named db.json in a data directory chosen by the operator’s environment (DATA_DIR) or a default data folder next to the code. The file is written by the bot process; it is not a hosted database in the current code.
  • No automatic retention period is defined in the code. Cases, warnings, notes, watchlist entries and configuration remain until they are deleted or changed with Uranium’s commands, the data file is removed by the operator, or the server record is otherwise cleared. A retention period, if the operator wants one, needs owner confirmation.
  • Deletion tools that exist in the code include deleting a case, removing or clearing warnings, removing a note, removing a watchlist entry, clearing a moderation-log setting, turning off AI or its chat channel, clearing AI chat memory, and logging out of the dashboard. Scheduled actions are removed after they run.
  • There is no self-service data-export or account-deletion page in the current dashboard code. To ask about records in a server, contact that server’s administrators; for deployment-level records, contact the bot operator. A published contact route for privacy requests needs owner confirmation.

8. Security — what the code does, and what it does not promise

  • Secrets such as the Discord client secret, bot token, session secret and Anthropic API key are read from environment variables. The project README instructs that secrets go in the hosting environment settings, never in GitHub. No secret values are included in these public pages.
  • Dashboard sessions use the cookie settings described in section 4, OAuth login uses a random state value that is checked on return, and dashboard APIs require a logged-in session.
  • Commands check the Discord permissions of the user running them and, where a command defines one, of the bot as well.
  • No other security guarantee is made. The code does not claim encryption of the JSON data file, a persistent or hardened session store, independent audits or certifications. The operator is responsible for securing the host, the data file and all environment secrets. Any stronger security statement needs owner confirmation and must be true of the live deployment first.

9. Your privacy choices and rights

  • You can choose not to use AI features, not to sign into the dashboard, and to leave any server that uses Uranium.
  • Server members can ask that server’s administrators about moderation records about them. Administrators have commands to view and delete cases, warnings and notes as described in section 6.
  • Depending on where you live, you may have legal rights over your personal information. Uranium’s code does not provide an automated rights-request system, so requests must go to the relevant server administrators or the bot operator. The operator’s contact details and response process need owner confirmation before any specific promise can be made here.
  • If you believe a record contains someone else’s sensitive information, tell the server’s administrators so they can remove it with the deletion commands above.

10. Changes

This policy may be updated when the code or deployment changes. The “Last updated” date shows when it last changed. Practices that are not confirmed by the code should not be added to this page.
